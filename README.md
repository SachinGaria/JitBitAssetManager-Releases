# JitBit Asset Manager

**Official Windows x64 distribution and release notes**

JitBit Asset Manager is a Windows desktop application for administering JitBit assets through an API-first workflow, with controlled authenticated web-session support for functionality that is not exposed reliably through the API.

This repository contains **production distribution packages, checksums, and release information only**. Application source code is maintained separately.

## What the application does

### Asset search and viewing
- Search assets using Asset # and other supported identifiers.
- Search by Serial Number and Employee Alias when required.
- Exact-match verification is used for targeted Serial # and Employee Alias searches.
- The main results table supports filtering, column visibility, copy/selection workflows, and horizontal/vertical scrolling.
- Search results are hydrated from current JitBit data so previously returned values are not intentionally reused as stale asset records.

### Single asset editing
- Open an asset and edit supported fields from a structured editor.
- Required fields and field types are validated before saving.
- Selection/dropdown fields use JitBit metadata rather than treating every field as free-form text.
- Assigned To is handled through the authenticated assignment workflow.
- The editor keeps read-only/reference information visible for review while protecting fields that should not be changed through normal editing.

### Bulk Operations
Bulk Operations provides two modes:

**Update**
- Resolve a list of assets by supported identifiers.
- Validate the workbook before applying changes.
- Control concurrency for high-volume operations.
- Review a live Asset Preview while assets are being resolved.
- See operation results as individual updates complete.
- Export the proposed update data.
- Create a ready-to-fill update template.

**Create**
- Generate a JitBit-compatible workbook template.
- Validate workbook data before import.
- Create multiple assets with controlled concurrency.
- Review validation and operation results.

### Safe blank-field updates
Bulk Update includes:

**Leave empty fields intact when updating**

When enabled, blank workbook cells are ignored. Existing JitBit values remain unchanged, while populated cells are applied.

This makes a workbook like:

| Name | Asset Status | Employee Alias | Notes |
| --- | --- | --- | --- |
| 123456 | Refurbished | | Service completed |
| 123457 | | user@example.com | |

behave as a targeted update rather than a "clear everything I forgot to fill in" operation.

Name is used as an identifier and is not overwritten by the bulk update operation.

### Live Preview
Bulk Preview is progressive:
- rows appear as validation resolves assets;
- successful updates refresh the corresponding row;
- the user does not need to reload the preview just to see changes made by the current operation.

### Excel workflows
- Generate workbook templates from the current JitBit field definitions.
- Import update/create workbooks.
- Export update data.
- Handle typed fields and SelectionCombo/dropdown values using the application's metadata layer.

### Environments
The application supports separate operational environments where configured:
- LIVE / PRODUCTION
- STAGING

The active environment is shown clearly in the interface, and environment-specific authentication, API configuration, web-session state, metadata, and logging context are kept separate.

### Access control
The application uses the authenticated JitBit account information available to it to determine the user's account type.

Role-aware behavior includes:
- administrator-only tooling such as Live Logs;
- protected reference/core fields for non-administrative users;
- optional administrator-only staging enablement;
- explicit production environment visibility.

### Live Logs and audit history
Administrators can inspect:
- application activity;
- asset changes;
- JitBit user;
- account type;
- Windows user;
- machine;
- environment;
- asset;
- action;
- change details.

When a common shared log folder is configured, participating installations write their events to a shared feed so administrators can review activity generated by multiple users and machines.

The Live Logs window refreshes automatically and uses defensive asynchronous loading so a transient log-file problem does not terminate the application.

Application logs and asset history are also kept locally for troubleshooting and historical review.

### Diagnostics and profile
Profile and Diagnostics views expose operational information such as:
- current environment;
- API connectivity;
- portal authentication state;
- JitBit account type;
- current Windows user and machine;
- configuration and connection diagnostics.

### Theme and usability
The desktop application includes:
- Light and Dark themes;
- keyboard shortcuts;
- copy-friendly read-only fields;
- configurable grid columns;
- responsive editor layouts;
- dedicated Bulk Preview and Operation Results areas.

### Updates
The application includes an in-app updater.

Update flow:
1. Check the public release feed.
2. Identify the latest version.
3. Download the Windows x64 ZIP.
4. Display download progress.
5. Verify the ZIP with SHA-256.
6. Stage the verified package before installation.
7. Wait for the running application to close.
8. Replace the installed files.
9. Restart the application.
10. Clean temporary updater files.

The updater also contains a bootstrap path so it can extract the updater script from a verified package when an older installation does not yet contain the updater.

### Distribution package layout
The Windows package is intentionally structured so that only the main executable is at the application root:

    JitBitAssetManager.exe
    .playwright\
    Support\
        Apply-Update.ps1
        UPDATE_README.txt
        update-source.json

This keeps the installation directory organized while retaining the runtime files required by Playwright and the updater.

## Release assets

Every production release should provide:
- JitBitAssetManager-win-x64.zip
- checksums.txt

The checksum file contains the SHA-256 hash for the application package.

## Installation

1. Open the desired release below.
2. Download JitBitAssetManager-win-x64.zip.
3. Extract the ZIP to a local application folder.
4. Run JitBitAssetManager.exe.
5. Connect using the JitBit API credentials used by your environment.

## Updating from inside the application

Open **Profile** and choose **Check for Updates**.

Later releases can be installed directly from inside the application without manually replacing the executable.

## Important operational guidance

This application can perform real asset changes in Live / Production.

Before large operations:
- verify the environment indicator;
- validate the workbook;
- review the preview and operation results;
- start with a controlled asset set where practical;
- review logs after completion.

Do not publish API tokens, browser authentication data, employee personal information, asset records, or internal secrets to this repository.
